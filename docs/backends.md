# Backend operational facts

> Verified on macOS unless marked **[web]**. Re-check version-sensitive details.

## Antigravity (`agy`)

- Google's terminal agent, successor to Gemini CLI. Auth = the user's Google login (OS keyring), no API key. Config under `~/.gemini/antigravity-cli/`.
- **Effort is baked into the model id** (`gemini-3.7-flash-high|-medium|-low`; no un-suffixed id). The registry stores the base id + `defaultEffort`; `backendModelId()` appends the suffix. `agy models` lists current ids.
- Headless: `agy -p "<prompt>"` (+ `--model`, `--dangerously-skip-permissions` for tools, `--add-dir`, `--print-timeout`, default 5m). **No JSON output mode.**
- **agy ignores its spawn cwd** — it treats the FIRST `--add-dir` as the workspace. Delegation must pass the caller's repo as the first `--add-dir` (temp answer dir second) or all edits land in the wrong directory and vanish.
- stdout capture works headless (piped, no TTY) as of agy 1.0.6 — no `node-pty` needed. If a future agy regresses (symptom: hangs to `--print-timeout`, 0 bytes), fall back to a pseudo-TTY or answer-file-only capture.
- **The per-model quota list lags `agy models`.** Verified on agy 1.1.12 (2026-08-13), re-verified on agy 1.1.22 (2026-09-01) and 1.1.24 (2026-09-02): `agy models` offers `gemini-3.8-flash-{high,medium,low}` and `gemini-3.7-flash-{high,medium,low}`, but the quota endpoint itemises `gemini-3.6-flash-{high,medium,low}`, for 3.7 only a single `gemini-3.7-flash-tiered` entry (no per-effort ids), and nothing at all for 3.8, so `evaluateAgyPreflight` finds no entry and proceeds with `model "…" not in quota snapshot; proceeding`. Runs work; only the per-model exhaustion guard is missing. The Gemini *group* windows still cover it, and `gemini-3.6-flash` stays registered as the newest flash tier the guard can see. Mapping the 3.7 ids onto `-tiered` in `AGY_CANONICAL_TO_NATIVE` is possible but unverified: nothing confirms `-tiered` is the bucket those runs draw from.
- **Quota death shows up as an empty answer, exit 0** (~6s). The quota preflight guards this. Quota is per model GROUP (all Gemini tiers share weekly+5h windows); each request injects ~24k system tokens, so don't loop trivia. **[web]**
- `--continue` resumes the most-recent conversation GLOBALLY — cross-contaminates concurrent runs; never use it for parallel calls.
- **Image generation**: agy exposes a `generate_image` tool with parameters `Prompt`, `ImageName`, `AspectRatio` (`1:1`, `16:9`, etc.), and `ImagePaths` (for image-to-image/reference edits). Renders land outside the cwd in `~/.gemini/antigravity-cli/brain/<uuid>/<name>_<epochms>.jpg` (JPEG, ~550 KB at 1024x1024). agy has no image quality knob.

## Codex

- `$imagegen` in a `codex exec` prompt renders with gpt-image-2 on the ChatGPT login — no `OPENAI_API_KEY`. Version gates: `MIN_CODEX_IMAGE` (image), `MIN_CODEX_STRUCTURED` (`--output-schema`/`--output-last-message`); a stale codex silently hangs on `$imagegen`.
- **`codex exec` is an agent and will silently substitute a code-drawn (PIL) image** for the real render if it judges the output imperfect. Always forbid redraw in the prompt, and size-check the file: a real gpt-image-2 PNG is hundreds of KB; a fake is ~10–30 KB (the `>100 KB` check). Raw renders cache at `~/.codex/generated_images/<uuid>/ig_*.png` — used for attribution.
- **Sandbox matrix**: tools-mode delegation needs `--dangerously-bypass-approvals-and-sandbox` — the sandbox blocks both the network and OS-keyring access that downstream CLIs (e.g. agy) require, even with `network_access=true`. `image-gen` uses `-s workspace-write` (its `image_gen` tool is codex-internal, not a sandboxed shell). No-tools delegation uses `-s read-only`.
- **`--full-auto` was REMOVED from `codex exec` in 0.147.0** (verified 2026-08-17; it printed usage and exited 2). `codex exec` has no `-a/--ask-for-approval` either — it never prompts, so the old `--full-auto` semantics are exactly `-s workspace-write` (`codex exec` reports `approval: never, sandbox: workspace-write`). The surviving replacement flag `--approve-for-me` is something else: it routes escalations through an automatic review pass. Every `CodexApproval` value now maps straight to a sandbox mode.
- `--output-schema` uses OpenAI strict structured outputs: `additionalProperties: false` AND every property in `required` — optional fields must be nullable, not omitted. A lax schema 400s.
- `-i ref.png` (reference images) is space-variadic — prompt goes BEFORE `-i`, multiple refs comma-separated.
- **The auth.json access token expires every ~10 days and only the codex CLI refreshes it.** Our quota probe reads `~/.codex/auth.json` directly, so a stale token surfaced as a hard `401 — run any codex command once`. The CLI refreshes lazily when it boots its auth manager: `codex mcp list` does it in ~0.6s with no model call and no quota cost; **`codex login status` does NOT refresh** (verified 2026-08-16, codex 0.147). `fetchCodexQuota` therefore runs `codex mcp list` on a 401 and retries once — delegation itself never needed this, `codex exec` refreshes on its own.
- **No quality/size parameters anywhere.** Verified tool schemas: codex `prompt`, `referenced_image_paths`, `num_last_images_to_include`; grok `image_gen` `prompt`, `aspect_ratio`; agy `generate_image` `Prompt`, `ImageName`, `AspectRatio`, `ImagePaths`. There is no `--quality` flag as a result (removed 2026-07-24 — it only appended prose to the codex prompt); `--size` was replaced by `--aspect-ratio` (2026-07-24). Each seat renders a fixed format (codex PNG; grok and agy JPEG, no format parameter on any of them) and aibridge dropped ImageMagick entirely (2026-07-24) — no convert, no resize.

## Grok

- **`grok models` is NOT an auth signal** (verified 2026-08-17, grok 1.0.4): it prints `You are not authenticated.` and falls back to a static model list even while `grok -p` answers fine and `~/.grok/auth.json` is valid — it exits 0 either way. Reading that string was gating `ensureGrok`, so it failed every grok `image-gen` and `probe` outright. `ensureGrok` is now a version check only (like `ensureClaude`); a genuinely signed-out grok is caught downstream off the CLI's own refusal text in `run.ts`. `refreshGrokAuth` still spawns `grok models` for the side effect alone, output ignored — now driven by the `expires_at` check in `getGrokAuth` rather than by a 401 (see decisions.md, 2026-08-21).
- **grok images: Imagine 2.0, called directly, and no transparency at all** (verified 2026-08-17, rewired 2026-08-20; grok-build source + live `api.x.ai`). aibridge no longer spawns the grok CLI to render: `driver-grok/generateImage.ts` POSTs to the same endpoints itself (see decisions.md for why). The contract, read off `image_{gen,edit}/mod.rs` and confirmed live: `POST /v1/images/generations` takes `{model, prompt, n, aspect_ratio, resolution:"1k", response_format:"b64_json"}`; `POST /v1/images/edits` takes the same minus `aspect_ratio`, plus refs as base64 data URLs — **one ref goes in `image: {url}` with `aspect_ratio` omitted** (the API infers ratio from the input and ignores the field), **two or more go in `images: [...]` with `aspect_ratio` required**. Bearer is the OIDC key from `~/.grok/auth.json`. Reference images need no client-side compression: a 2.5 MB PNG data URL was accepted verbatim, HTTP 200 in 15s, reference honoured. **`/v1/images/generations` silently ignores `image`/`images`** — it returns 200 and a paid render that used none of the reference, so the gen-vs-edit branch must never fall back to the other endpoint. Both CLI tools default to `grok-imagine-image-quality`; aibridge pins `grok-imagine-image-2.0` as a plain `model` field — current model, $0.04/img at low+1k vs $0.05 for quality. The old `GROK_IMAGE_{GEN,EDIT}_MODEL_OVERRIDE` env plumbing is gone with the CLI spawn. **Alpha is impossible on this seat:** the API's real schema is `model, prompt, n, aspect_ratio, resolution (1k|2k), quality (low|medium|high), response_format, size, style, user, moderation` — every transparency-ish field (`background`, `transparent`, `output_format`, `alpha`, `mask`, …) is silently ignored, and 2.0 returns `mime_type: image/jpeg`, 3-component JPEG, even for an explicit "transparent background, PNG with alpha" prompt and for an `/images/edits` "remove the background" pass. x.ai's Image 2.0 background-removal claim is a Grok Imagine app feature, not an API one — the app sends a `#00ff00` chroma-key prompt to that same endpoint and keys the green out itself, which is what `image-gen --transparent` now does locally (see decisions.md).
- **grok inherits the operator's Claude config, and that broke image-gen** (verified 2026-08-20, grok 1.0.5). `grok inspect` in an empty temp dir reports 190 skills and loads `~/.claude/CLAUDE.md` as `<user_rules>`, plus Claude's MCP servers. A delegate therefore reads the operator's own agent instructions as if they were the task. Concretely: a "load the unslop skill before you do anything" rule made grok spend all four of `image-gen`'s turns on MCP `search_tool`/`use_tool` discovery and never call the image tool, failing ~1 in 3 with `max turns reached` (four such sessions are recorded under `~/.grok/sessions/*imagegen*`). Longer prompts failed more often: the model reads a big prompt as a real task worth prepping for. `--tools image_gen` does NOT contain this, because it allowlists only *built-in* tools and MCP tools bypass it. The fix is four env vars on every grok spawn (`GROK_CLAUDE_{RULES,SKILLS,MCPS,AGENTS}_ENABLED=0`, see `grokEnv()` in `driver-grok/grok.ts`), which flip those sources to `[disabled]` in `grok inspect` and drop the MCP block entirely. It does not shrink grok's own bundled/plugin skills: ~88 KB of skill listings still rides on every grok call.
- **grok's `plain` and `json` output glue every assistant turn together; only `streaming-messages-json` separates them** (verified 2026-08-20, grok 1.0.5). A run that narrates before answering returns one blob with the final answer welded onto the tail of the narration and **no separator**: `"...reading \`a.txt\`.PASS\n"`. `--output-format json` is no better — its `text` field is the same welded string, so the concatenation happens inside grok, not in our capture. This silently broke `review`, whose stdout contract needs the verdict alone on a line (`/^PASS\b/` never matched), and it prefixed every `subagent` / `plan` / `implement` answer with the model thinking out loud. `--output-format streaming-messages-json` emits NDJSON frames in the Anthropic wire format, one per turn, so `run.ts` reads the answer off those frames in a fixed order: a non-empty terminal `result.result` first (grok's own docs call it "the final assistant message text"), then the last non-empty `text` from a `message.role === "assistant"` frame as the backstop. Two traps in those frames: content blocks interleave `thinking` and `text`, and **only `text` is answer material**; and a grok that fails before the protocol starts prints plain text instead, so the raw stream must stay the fallback or the sign-in check goes blind.
- Grok uses print mode and maps effort to `--reasoning-effort`. It is capped at
  about 30 requests per minute and 1,000 messages per day. The quota probe calls
  `GET /v1/billing?format=credits` on `cli-chat-proxy.grok.com` with the token
  from `~/.grok/auth.json`. It returns weekly credit remaining and a per-product
  split. Per-minute and daily limits are not queryable; they surface as HTTP 429.

## Claude

- Claude uses print mode and maps effort to `--effort`.
- Quota comes from the CLI usage command and includes session and weekly windows.
