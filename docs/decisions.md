# Architecture decisions

> Decision log since 2026-06-08. See [`backends.md`](backends.md) for runtime
> facts and [`AGENTS.md`](../AGENTS.md) for current development instructions.

## Active decisions

- **Skill + CLI, not an MCP server.** The skill carries judgment/prompt-craft as on-demand context; the CLI owns brittle execution. MCP's ~60s default tool timeout fights multi-minute delegations, and cross-client reuse wasn't needed. If another surface ever needs these tools, wrap this same CLI in a thin MCP server.
- **Two-step distribution** (2026-07-24): `@aibridge/*` packages on npm + a prose-only skill that runs `npx -y @aibridge/cli` zero-install. Transparency (users see exactly what's installed), standard skill-wraps-a-CLI pattern, and it deleted the entire committed-bundle gate apparatus.
- **OIDC version-triggered publishing** (modeled on fishballapp/acme): bump a package version, merge to main → `publish.yml` verify job (full gates + pack/consumer smoke) then OIDC publish with provenance, skip-if-exists. First-ever publish of a NEW package needs a one-time manual bootstrap + Trusted Publisher config.
- **Monorepo layout**: `packages/proc` (spawn/capture) ← `packages/driver-{agy,grok,codex,claude}` (per-CLI drivers: args, capture protocol, quota, probe) ← `packages/cli` (stricli app, models registry, backend-switch-free delegate). Structural `AgentCliDriver` contract (`probe`/`run`/`quota?`/`generateImage?`) defined in the cli package; drivers conform structurally — no shared contracts package. `AGY_CANONICAL_TO_NATIVE` lives in `driver-agy` to avoid a dependency cycle.
- **`@stricli/core` for command orchestration** — typed `buildCommand` routing, generated help; exit-code contract (0 ok / 1 operational / 2 bad args / 3 quota refusal) preserved by normalizing stricli's framework codes post-`run`, locked by in-process tests on both the dev entry and published bin.
- **Canonical model slugs** `<vendor>-<cli>/<model>[-<effort>]`, no aliases; effort maps to each backend's own knob. Registry in `packages/cli/src/models.ts`.
- **Cross-model seats**: grok plans/reviews, gemini implements — a model never reviews its own diff. These are *recommendations carried by the skill*, not CLI behaviour (see "The CLI chooses nothing").
- **The CLI chooses nothing** (2026-07-25): `--model` is required on every command that spends a delegate (`plan` / `implement` / `review` / `subagent` / `image-gen`; the read-only `quota` / `models` / `runs` take none), `--out` on `plan` / `review` / `image-gen`; `DEFAULT_MODEL` / `DEFAULT_IMPLEMENTER` / `DEFAULT_IMAGE_GEN` are deleted. `--timeout` and `--base` keep defaults — a timeout is a safety bound and `HEAD` is the only sensible working-tree base, neither is a choice about whose quota burns.
- **Facts in the CLI, judgment in the skill** (2026-07-25): `aibridge models [--json]` prints registry facts (accepted efforts, image format, pinned backend id) straight from `models.ts`; the seat routing table lives only in `SKILL.md`, and `brief` strings state login/quota shape, never routing verbs. Rationale: that table was revised four times inside one design conversation — taste moves at conversation speed, facts at vendor speed, and only one of those should cost an npm release. Corollary: no duplicated seat tables in reference docs (the one in `reference/subagent.md` was deleted after it rotted).
- **image-gen exposes only what the backends actually accept** (2026-07-25): `--aspect-ratio` (a real tool parameter on agy and grok, a prompt hint on codex), `--out` required with a seat-matched extension, and no image processing of any kind — the output file is the model's own bytes. Verified from all three tool schemas: none takes a quality or size parameter, and each seat renders one fixed format (codex PNG; agy and grok JPEG). **Amended 2026-08-17:** `--transparent` is the one deliberate exception — it chroma-keys locally and always writes PNG, because no backend can be *asked* for alpha on a JPEG-only seat. The rule it preserves is the real one: no processing that fakes a capability the model could have provided (the deleted `--size` upscale did exactly that). Do not read this entry as a licence to add resizing, format conversion or quality knobs back.
- **A seat whose quota the preflight can still read is worth keeping** (2026-08-13): agy 1.1.12 serves `gemini-3.7-flash-*` from `agy models` but its quota endpoint itemises only up to `gemini-3.6-flash-*`, so a 3.7 run prints `not in quota snapshot; proceeding` and loses the per-model exhaustion guard (the failure it guards is agy's silent empty answer, exit 0). `gemini-3.7-flash` becomes the recommended flash seat; `gemini-3.6-flash` stays registered until the quota endpoint catches up.
- **A newer model replaces a seat only when it is strictly better** (2026-08-13): grok CLI 1.0.3 made `grok-4.6` its default, but 4.5 and 4.6 differ in character rather than rank — 4.6 is the reasoning tier (a slightly weaker `gpt-5.6-sol` / `opus-5`, so: `plan`, `review`), 4.5 the better blind implementer of an already-detailed plan. Both stay registered, and `SKILL.md` carries the split. The per-class-pinned rule below is about never pinning a *moving* alias, not about capping a class at one seat. Re-verified against grok 1.0.3 at the same time: `-p/--single`, `--model`, `--reasoning-effort`, `--permission-mode bypassPermissions`, `--tools`, `--max-turns`, `--json-schema`, `grok models` and the `/v1/billing?format=credits` probe are all unchanged — the driver needed no change.
- **Registry is per-class, pinned** (2026-07-25): the latest model of each vendor class gets a seat, each pinned to an exact id. Image capability is keyed on *backend*, not model — `google-antigravity/claude-opus-4-6-thinking` renders while `anthropic-claude/opus-5` cannot, same family, different CLI.
- **Nothing assumes which agent is orchestrating** (2026-07-25): aibridge is installed from Claude Code, Cursor, Codex, Gemini CLI and others, so shipped text states the rule — *whichever seat runs on your own provider is your last resort, since it spends the pool you are already burning* — and names Claude only as an example.
- **Verify vendor surfaces against the tool schema, not the docs** (2026-07-25): `--quality`, `--size` and "grok has no usage probe" were all long-standing claims in this repo that turned out false the moment they were checked against a real schema or a real render. Prefer one cheap probe over an inherited sentence.
- **`image-gen` runs the same quota preflight as the delegation commands** (2026-08-21): it was the only command that would spend a paid render against an exhausted account and find out from the backend. It now takes `--preflight` / `--no-preflight` (default on) and refuses with exit 3, placed after every local validation so a bad `--out` or `--aspect-ratio` still fails with no network call. The refusal's fallback clause is command-aware: suggesting `subagent --model sonnet` is useless here, since no claude seat renders images, so `image-gen` names the other image seats instead. No `--json` error shape was added — this command reports every other failure as prose on stderr, and inventing a machine contract for one branch of it would be worse than none.
- **Refresh the grok token before the request, not after a 401** (2026-08-21): `~/.grok/auth.json` carries `expires_at` right next to `key`, and `readGrokAuth` ignored it. Both direct-API callers fired with whatever token was on disk and refreshed only once the server said 401. On `/v1/images/edits` that costs a full wasted upload, since the reference images go up as uncompressed base64 and the body is serialised and sent twice before any render starts. It was also blind: `refreshGrokAuth` swallows every error, so a revoked session and a successful refresh look identical until the second 401 lands. `getGrokAuth` (`driver-grok/auth.ts`) now reads `expires_at`, spawns the CLI refresh only when the token is within a 2-minute skew of expiry, and re-checks afterwards: still expired means `AuthExpiredError` and a `grok login` instruction, said before anything is uploaded. A missing or unparseable `expires_at` counts as valid, so api-key and `auth_provider_command` modes never spawn the CLI. The 401 retry stays in both callers as the backstop for a token revoked before its `exp`. Doing the OIDC refresh over HTTP ourselves with the `refresh_token` was rejected: it saves the ~1.3s spawn and buys a race with the CLI's own `auth.json.lock`.
- **Expired auth refuses, exhausted quota warns** (2026-07-29): quota-probe failures used to degrade uniformly to `warning: …; proceeding`, so an expired grok token let a full delegate run spawn unauthenticated and return no report. Now `AuthExpiredError` (`packages/proc`) tags auth failures across all three quota probes, preflight returns `kind: 'auth'` and refuses (exit 3) — `--no-preflight` is called out as *not* a workaround, since it only sends the delegate in signed-out. Transient/network probe failures still warn and proceed. Grok additionally self-heals: a 401 on the billing endpoint runs `refreshGrokAuth` (`grok models`, spawned for the token refresh alone — its *output* stopped being trustworthy in grok 1.0.4, see the 2026-08-17 entry) and re-reads `auth.json` once before giving up. Codex and agy only refuse — neither has a cheap known refresh command worth inventing.
- **No corepack; pnpm pins itself via `devEngines.packageManager`** (2026-08-14): corepack is gone from Node 25+ (TSC vote, Mar 2025) and pnpm no longer documents it, so the `packageManager: "pnpm@11.5.2+sha512…"` pin (corepack's hashed format) and `corepack enable` in CI were a dead-end path — working only because the runners still pin Node 24. Now `devEngines.packageManager` `{ name, version, onFail: warn }` + `pmOnFail: download` in `pnpm-workspace.yaml`, which pnpm 11 manages natively: it downloads and re-execs the pinned version, and records the resolution in `pnpm-lock.yaml` (the legacy field never did). The onFail split is not cosmetic — `devEngines` is a *shared* npm field, and npm 11 hard-fails `EBADDEVENGINES` on any `onFail` outside `ignore`/`warn`/`error`, which took down the publish job's `npm view` calls at repo root on the first attempt. pnpm-only behaviour belongs in pnpm's own settings file. CI installs pnpm with `pnpm/action-setup@v6` — the first line that reads `devEngines` — kept alongside `actions/setup-node` rather than swapping in the newer `pnpm/setup@v2`, because the publish job needs setup-node's `registry-url` for OIDC trusted publishing and that path isn't testable pre-merge. Local installs are the standalone script + `pnpm self-update`.
- **Workflow actions track major tags, and the Node version comes from `engines.node`** (2026-08-14): `uses: actions/checkout@v7` etc., not commit SHAs — one less thing to hand-bump, at the cost of a mutable ref. `actions/setup-node` reads the version from `node-version-file: package.json`, so `engines.node` (`>=24.11`) is the single source of truth; setup-node sorts candidates with `semver.rcompare` and takes the newest match — but with `check-latest` left at its default `false` it searches the *runner's tool cache* first, so CI actually runs Node 24.19.0 today, not the newest Node that satisfies the range. Any version in range is fine (the range is a floor, not a target); add `check-latest: true` to trade a download per run for the true newest. `package-manager-cache: false` was dropped — as of setup-node v7 that cache only engages when the declared package manager is npm.
- **A backend CLI's *output* is as breakable as its flags** (2026-08-17): a four-CLI re-verification sweep (codex 0.147.0, claude 2.1.233, agy 1.1.13, grok 1.0.4) found two breakages, and only one was a flag. (1) `codex exec --full-auto` was removed — codex printed usage and exited 2 before any image tool ran, so `image-gen --model openai-codex/*` was dead. Replaced with `-s workspace-write`; `CodexApproval` lost its `'full-auto'` member and now maps 1:1 to sandbox modes. (2) `grok models` began printing `You are not authenticated.` while signed in, and `ensureGrok` read that string as a verdict — silently killing every grok `image-gen` and `probe` with a false "not signed in". The lesson: a parsed *string* from another CLI is an undeclared API with no deprecation notice, strictly worse than a flag, which at least fails loudly. So auth checks moved to where the real signal is — `ensureGrok` is now a version check only (matching `ensureClaude`), and being signed out is detected off the CLI's own refusal text on the actual delegation, not a preflight. Everything else re-verified unchanged: agy's `-p`/`--model`/`--print-timeout`/`--add-dir`/`--dangerously-skip-permissions` and effort-suffixed model ids (agy's new standalone `--effort` flag is an alternative, not a replacement); claude's `-p`/`--model`/`--effort`/`--json-schema`/`--add-dir` and the `/usage` window lines the quota parser matches; grok's `-p`/`--model`/`--reasoning-effort`/`--permission-mode`/`--tools`/`--max-turns`/`--json-schema`; codex's `-c`/`-C`/`-m`/`-s`/`--skip-git-repo-check`/`--output-schema`/`--output-last-message`/`--image`/`codex mcp list`. Every registered `backendModel` id still exists on its CLI.
- **`--out` destination is a skill convention, not CLI behaviour** (2026-08-17): a kept asset renders straight to its real home (`public/icons/settings.png`) — no scratch-then-move — while working artifacts (plans, reviews, draft images) go to `<repo root>/.aibridge/`, a gitignored sketchpad inside the repo the user is already in, so output is one click away instead of buried in a system temp dir. The skill also checks `git check-ignore -q .aibridge/` before the first write and asks the user to ignore it if not — the trailing slash matters: with the usual dir-only `.aibridge/` rule, the slash-less form exits 1 while the directory does not exist yet, i.e. exactly when the check runs (verified across both `.gitignore` spellings × dir present/absent). Carried entirely by `SKILL.md` + reference docs; the CLI still requires an explicit `--out` and defaults nothing (see "The CLI chooses nothing"). A default `--out` of `.aibridge/` was considered and rejected: the required flag is the forcing function that makes the agent decide where the file belongs — a default would quietly land kept assets in the sketchpad and hide the decision.
- **Transparency is a goal the caller states, not a mechanism it picks** (2026-08-17): `image-gen --transparent` is valid on every image seat and always writes PNG; the CLI owns the per-backend split, so no caller needs a capability table. codex is asked for real alpha and its bytes pass through; grok/agy — which cannot emit alpha at any setting — get a flat `#00ff00` chroma-key backdrop appended to the prompt, and `transparency.ts` keys that green to alpha locally. There is no separate grok edit model to reach for: `/v1/image-generation-models` lists only `grok-imagine-image`, `grok-imagine-image-2.0`, `grok-imagine-image-quality`, every edit-model id (`grok-imagine-image-edit`, …) 404s, and `/v1/images/edits` takes those same three (the reseller `xai/grok-imagine-image/edit` naming is a *route*). The Grok web UI's "background removal" is this exact trick — a chroma-key prompt to that endpoint, keyed client-side — which is where the clause wording came from. Measured on a real Imagine 2.0 render: backdrop clusters at `(16,250,19)`–`(18,250,20)` and the keyed share is flat from tolerance 40 to 100, i.e. no ambiguous mid-zone; an end-to-end run keyed 65.4% with zero green left in the subject. Two design calls carry the weight: the clause rides on the **first** render (no second paid call — the web UI needs an edit pass only because its image already exists), and despill is **neighbour-gated** so it touches the JPEG fringe ring rather than grey-ing out any green pixel. Capability lives in the registry (`IMAGE_ALPHA` per backend) so it surfaces in `image-gen --help`, `models` and `models --json`; the run reports which path it took. Two pre-spawn refusals protect the money: `--transparent` with a `.jpg --out`, and a prompt asking for transparency on a chroma seat without the flag. Known and documented costs: binary alpha (no hair/glass), a faint model-drawn contact shadow survives as a pale halo, and a **strongly green subject is keyed away with the backdrop** — all three are codex's job instead. An earlier white-backdrop version of this was rejected first (see history).
- **Bypass a backend CLI when its "tool" is one HTTP call, and give delegates the task rather than the operator's rulebook** (2026-08-20). `image-gen` on a grok seat used to spawn `grok -p --tools image_gen --max-turns 4` and ask the model to call its image tool. That wrapped a single POST in an agent loop, and the loop lost: grok reads `~/.claude/CLAUDE.md` as user rules and attaches Claude's MCP servers, so ~1 run in 3 burned every turn on skill-loading and died with `max turns reached` (see backends.md). `driver-grok/generateImage.ts` now POSTs `/v1/images/{generations,edits}` itself with the bearer from `~/.grok/auth.json`. The rewrite **deleted** the turn budget, the stdout path-scraping, the `~/.grok/sessions` scavenging fallback, and the prompt-craft that asked a model to guess an API contract ("pass aspect_ratio only if the tool accepts it") — a contract we can now simply encode. Two facts make it safe to keep this thin: reference images need no compression (a 2.5 MB PNG data URL is accepted verbatim), so `driver-grok` stays dependency-free with no `sharp`; and the gen-vs-edit branch has **no fallback**, because `/generations` silently ignores reference images and would hand back a plausible paid render that used none of them. The generalisable rule: a vendor CLI's agent loop is a liability when we already know exactly which call we want. Reach for the CLI when we need judgment, and for the API when we need one request. Cost of the choice: an undeclared HTTP surface. That is the same bet the quota probe already makes, and it is a *payload* rather than parsed prose, so a vendor change fails loudly with a non-200 instead of silently returning the wrong thing. Side effect worth knowing: `image-gen` on a grok seat no longer needs the grok CLI on `PATH` at all — only `auth.json` and network. The CLI is reached only to refresh the token (on a 401 here; amended 2026-08-21 below to refresh on `expires_at` first, with the 401 retry kept as the backstop). The same `GROK_CLAUDE_*_ENABLED=0` fix is applied to every grok spawn, so `subagent` / `plan` / `review` — which genuinely do need the agent loop — stop inheriting the operator's rules, and stop being told to delegate back into aibridge.
- **Read a backend's answer off its message stream, not its console output** (2026-08-20). `review` on a grok seat kept printing `could not parse a verdict line` and then the verdict anyway, because grok welds the final answer onto the tail of its narration with no separator (see backends.md). The tempting fix was to loosen review's verdict regex to match a tail-anchored `PASS`. That would have been a fix at the wrong altitude: the verdict contract was only the loudest victim, and every `subagent` answer was equally polluted, just less visibly. `driver-grok/run.ts` now runs `--output-format streaming-messages-json` and returns the terminal `result.result` when it has one, falling back to the last assistant turn, so **all** callers get the answer without the narration. Deliberate calls inside that: `thinking` blocks are dropped rather than concatenated (they are not answer material); the raw stream stays the fallback when nothing parses, or a grok that refuses before the protocol starts would slip past the sign-in check; and the run log gets a line-buffered unwrapper so `aibridge runs --watch` stays prose instead of becoming a JSON dump. The rule this generalises: when a vendor CLI offers both a human-readable and a machine-readable stream, parsing the human one is a bug waiting for the vendor to add a sentence.
- **A capability has to read the same in every surface an agent looks at** (2026-08-22). The skill's subcommand table described `review` as "Review the working-tree diff (or a plan)". `--base` has always taken any ref or range git accepts, but on that sentence an agent ruled `review` out for work it had just committed, fell back to `subagent`, and hand-rolled a diff into a file. The wording was fixed in four places in one go, because a doc fix alone would have left the trap: the skill table, `reference/review.md` (which now leads with worked `--base HEAD~3` / `--base main` examples, since reviewing commits is the *normal* end-of-session case), the CLI's own `--help` briefs — the second place an agent checks, and it said "Review working tree diff or plan contract" too — and the delegate prompt itself, which told the reviewer model to "inspect the working tree diff against base 'HEAD~3'" and now names `git diff <base>`. The rule: when a flag widens what a command can do, grep for the *old* description, not the flag name.
- **Skill docs carry how-to; rationale lives in `reference/why.md`** (2026-08-22). `SKILL.md` and the five references argued for their own rules inline, so every agent paid for the arguments on every read and the imperatives got buried in them. Rules stay as imperatives, the arguments moved to one grep-able doc linked once from `SKILL.md` with a specific trigger — read it when a rule looks wrong for your case, which is the only moment rationale changes a decision. 363 lines out, 261 in. The real risk showed up in the cross-model review of the cut, and it is worth expecting next time: **compression silently strips qualifiers**. Two majors, both from dropped clauses rather than dropped facts — routing lost "for high-risk designs" and so read as *gate every implement*, which is a grok run per implement against a ~1k msgs/day cap; and the `--out` bullet lost "except chroma-keyed `--transparent`", contradicting the transparency section three bullets below it. So a docs compression gets a review pass of its own, aimed at qualifiers.
- **A publish is not done until the version resolves** (2026-08-22): `pnpm publish` exiting 0 means npm accepted the PUT, not that the version is installable. npm stages a publish first and 404s the version until it finalises. On the 0.9.0 release that took ~4 minutes for `@aibridge/driver-grok` while its five siblings from the same run were already live — and since `@aibridge/cli` pins exact driver versions and publishes last, `npx -y @aibridge/cli` at `latest` was briefly unresolvable. Publishing in dependency order only protects consumers if each version is *visible* before the package that pins it goes out, so the loop now polls `npm view "$name@$version"` for up to 5 minutes after each publish and fails the job if it never lands. Failing is the right end state: re-running skips whatever already published (the existing skip-if-exists check), while continuing would ship a dependent against a version nobody can install. Two traps for anyone verifying a release by hand, both hit live: a 404 right after a green publish is probably staging rather than a failed publish, so poll before reaching for a fix; and re-publishing over a staged version returns `409 Cannot publish over previously staged version`, which marks the run red for something that was already fine.
- **Node ≥24.11, native TS dev loop** — packages' `exports` point at `src/*.ts`; Node runs workspace-linked TS directly (no build in dev). Erasable syntax only; tsdown builds `dist/` for publishing; `prepack` self-builds.

## History (superseded, kept as one-liners)

- *Welded plan gate* (one recursive codex call doing review+expand+build) → replaced by the decoupled `plan` → `implement` → `review` flow with the orchestrator approving the plan file between stages (2026-07-24).
- *Zero-dependency `node:util parseArgs` CLI inside the skill dir* → stricli + npm packages once bundling/publishing removed the zero-dep constraint (2026-07-24). Same change: `review` now rejects stray positionals (exit 2); stricli's additive flag spellings (`--flag=value`, `--help-all`) accepted.
- *Committed self-contained skill bundle* (`skills/aibridge/scripts/cli.mjs` + freshness/bare-copy/import.meta CI gates) → two-step npm distribution (2026-07-24).
- *Original repo/scope names* `fishballapp/ai-bridge`, `@ai-bridge/*`, `@aibridge/{agy,…}` → `ycmjason/aibridge`, `@aibridge/*`, `@aibridge/driver-*` (2026-07-24).
- *`image-gen --quality low|medium|high`* → deleted (0.2.0). It only appended `Render at HIGH quality.` to the codex prompt and was ignored elsewhere; no backend image tool has a quality parameter. A flag impersonating a knob.
- *`image-gen --size WxH` + ImageMagick resize/convert* → `--aspect-ratio N:M`, raw model bytes (0.2.0 → 0.3.0). No backend accepts pixel dimensions: a `--size 1536x1024` run was really a 1264x848 render upscaled 21% locally, reporting invented dimensions as if the model had produced them. The codex-only size validation (divisible-by-16, 0.65–8.3 MP) guarded a gpt-image-2 API knob the codex CLI never exposes.
- *`DEFAULT_MODEL` / `DEFAULT_IMPLEMENTER` / `DEFAULT_IMAGE_GEN`* → required `--model` on every delegating command (0.3.0). The defaults silently decided whose quota a run would spend.
- *`anthropic-claude/opus-5-1m` as a separate seat* → `anthropic-claude/opus-5` pinned to `claude-opus-5[1m]` (0.4.0), matching how Claude Code presents Opus 5.
- *White-backdrop `--remove-bg`, then no flag at all* → `--transparent` with a `#00ff00` chroma key (2026-08-17). The first scope keyed a flat *white* backdrop by corner flood-fill; it worked (`magick -fuzz 6% -floodfill`, interior white markings intact) but cost an extra paid edit pass and frayed on white-ish subjects, so it was dropped in favour of routing everything to codex — until the Grok web UI's actual request turned out to use a green chroma key, which separates cleanly, needs no flood fill, and rides on the first render. The flag was also renamed from `--remove-bg`: it named the mechanism, so every caller would have needed to know which seats it applied to.
- *"grok has no local usage probe"* → disproven (0.4.0). `GET /v1/billing?format=credits` on `cli-chat-proxy.grok.com` returns a weekly credit percentage plus a per-product split. The TUI's `/usage` was a red herring — it reads an in-memory per-session ledger (`x.ai/session/usage`) that resets on resume, not account quota. Per-minute/per-day caps remain unqueryable and surface only as HTTP 429.
